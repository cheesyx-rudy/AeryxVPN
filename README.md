# 🟡 LIKVID VPN

**Бесплатная агрегированная подписка с прокси-конфигурациями.**

Парсер собирает конфигурации из открытых источников, удаляет дубликаты и формирует единый список для импорта в совместимые VPN-клиенты.

## ⚙️ Как это работает

1. Парсер получает конфигурации из источников, перечисленных в `usual-sub/legacy/proxy_sources.txt`.
2. Извлекает поддерживаемые URI, удаляет дубликаты и отфильтровывает некоторые несовместимые конфигурации.
3. Сохраняет снимок в `usual-sub/legacy/parsed_proxies.txt`, чтобы режим очистки мог использовать тот же список.
4. Формирует итоговую подписку `usual-sub/legacy/proxies.txt`.

Для ручного запуска используется GitHub Actions. В workflow также настроен запуск по расписанию; доступны режимы `fresh` и `cleanup`.

- `fresh` — заново получить конфигурации из источников и сформировать новый список.
- `cleanup` — удалить номера конфигураций, перечисленные в `usual-sub/legacy/dead.txt`, используя сохранённый снимок без повторной загрузки источников.

## 🔌 Поддерживаемые URI

Парсер умеет извлекать ссылки следующих типов, если они присутствуют в источниках:

- VLESS
- VMess
- Trojan
- Shadowsocks (`ss`)
- ShadowsocksR (`ssr`)
- Hysteria / Hysteria2
- TUIC
- AnyTLS
- SOCKS / SOCKS5
- HTTP

Поддержка конкретной ссылки зависит также от VPN-клиента и его версии. Наличие ссылки в подписке не гарантирует, что сервер работает.

## 🧭 Маршрутизация Happ

В основную подписку `usual-sub/legacy/proxies.txt` встроена deeplink-ссылка
`happ://routing/onadd/...`. При добавлении подписки Happ получает профиль маршрутизации
**LIKVID VPN RU + Whitelist** и добавляет/активирует его.

Единственный исходный файл профиля:
`usual-sub/legacy/routing/LIKVID-RU-WHITELIST.JSON`.

При каждом запуске парсер:

1. Читает JSON-профиль и проверяет, что он корректен.
2. Обновляет `LastUpdated`.
3. Создаёт Base64 deeplink для Happ и записывает его в `LIKVID-RU-WHITELIST.DEEPLINK`.
4. Вставляет deeplink в `proxies.txt` перед списком прокси.

GitHub Actions сохраняет сформированные подписку, снимок прокси и файлы профиля в репозитории.

### Правила маршрутизации

- `GlobalProxy: true` — трафик по умолчанию направляется через VPN.
- `geosite:whitelist` и `geoip:whitelist` — напрямую.
- `geosite:category-ru` и `geoip:direct` — напрямую.
- `geosite:private` и `geoip:private` — напрямую.
- `geosite:win-spy`, `geosite:torrent` и `geosite:category-ads` — блокируются.
- `UseChunkFiles: true` — включено для более экономной работы с геобазами, что особенно полезно на устройствах с ограниченной памятью, включая iOS.

Профиль использует геофайлы по постоянным URL из `hydraponique/roscomvpn-geoip` и
`hydraponique/roscomvpn-geosite`. Обновление исходных файлов на стороне этих проектов не
означает мгновенного обновления у всех пользователей: Happ самостоятельно регулирует частоту
загрузки геобаз. После изменения профиля пользователь должен обновить подписку в Happ.

**Важно:** наличие правила в JSON само по себе не гарантирует, что категория присутствует в
подключённой геобазе или что конкретный сервис будет маршрутизироваться ожидаемым образом.
Проверяйте результат на реальном устройстве и в используемой сети, отдельно для iOS.

## 🛠️ Возможности парсера

- Получает источники из `usual-sub/legacy/proxy_sources.txt`.
- Извлекает поддерживаемые URI, в том числе из Base64-подписок и JSON.
- Удаляет дубликаты и пропускает конфигурации с неподдерживаемым параметром ML-KEM encryption.
- Ограничивает итоговый список 1000 конфигурациями.
- Определяет страну узла по IP и добавляет флаг, название страны и номер в имя конфигурации. Если определить страну не удалось, используется `Cluster Unknown`.
- Сохраняет снимок в `parsed_proxies.txt`, чтобы `cleanup` работал с тем же списком и нумерация не менялась.
- Формирует `proxies.txt` с заголовками подписки и deeplink-профилем Happ.

### Режимы запуска

- `fresh` — загружает источники, собирает новый список, обновляет снимок и генерирует подписку вместе с профилем Happ.
- `cleanup` — использует существующий `parsed_proxies.txt` и удаляет номера, указанные в `dead.txt`; источники заново не загружаются.

Workflow GitHub Actions поддерживает ручной запуск и запуск по расписанию. Сообщение GitHub о миграции `ubuntu-latest` — информационное уведомление о runner, а не ошибка парсера.
